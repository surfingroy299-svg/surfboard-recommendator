# Direction 03 — UX Model

## Entry
Three boards drop onto the table in sequence — thud, settle, springy rest —
into three slots with big role tags (REAL roles vocabulary, mocked
assignment). A one-beat teaching moment (P5): the center board wobbles once
under a hand cursor with the hint "grab me." First grab = tutorial done.

## Selection & manipulation
- **Grab a board** (pointer down + lift, or 1/2/3, Tab): it rises to focus
  height with spring; table dims slightly. **Flick horizontally = spin** with
  momentum that always **snaps to the nearest canonical face** (deck / rail /
  bottom / tail-view); arrow keys step faces. Release = settles back with
  weight.
- **Camera is fixed** (one slight dolly-in on focus). The user only ever
  controls boards — there is no camera to learn, no mode to confuse
  (structural mode clarity; the opposite pole from 01's station camera).

## Inspection & data reveal
Each snap face flips its own **face card** up from the table edge: deck =
role + why; bottom = "what the bottom does" (traits-derived, sketch-labeled);
rail = feel line (labeled); tail = tail note + data-gap honesty ("tail shape:
unknown — we don't guess", REAL data-gap rule). Dims live on a boarding-pass
style tag hanging off the nose: volume with the target-range meter (REAL
30.2–40.8 L bracket), length/width/thickness. Every number's tag flips to its
consequence line on tap (P12).

## Comparison
Grab one board, **drop it onto another slot** (or C) → **Face-off**: both
boards jump to center, same scale, auto-synchronized snap-spins (spinning one
spins both); between them a tug-of-war bar per trait pair (paddle ⇄ response,
stability ⇄ looseness — qualitative positions from 1–5 traits, REAL trait
values, PROTOTYPE ASSUMPTION pairing) and two oversized delta tags: "+ catches
waves earlier" / "− less bite when it's steep". Exit (Esc / pull apart) —
boards spring home to slots; nothing is lost.

## Lock / reject / replace (the hero loop)
- **Lock**: slam the slot clamp (click the clamp, or L) — a chunky mechanical
  clasp closes over the tail with a snap; the tag stamps LOCKED.
- **Reject**: pull the eject ring (or X) — the board spring-launches off the
  table (fast, comic, safe); the slot flashes empty for a beat.
- **Replace**: a new board slides in along the table groove, wearing a swap
  tag: "IN: G Skate — same small-wave job, looser off the top. OUT: felt too
  similar to your locked pick." (PROTOTYPE ASSUMPTION, trait-grounded, A2.)
- **Refine chips** sit at the table edge: `easier paddling` `more forgiving`
  `more response` — tapping one ejects the unlocked board and deals a
  replacement matching the chip (mocked against the fixed pool, labeled).
Locked boards visibly cannot eject (clamp rattles, tag wiggles — feedback,
not failure silence).

## Recovery & modes
Only two states exist: table and face-off; the state name is stamped in the
table corner. Esc always returns to table. Undo toast after every eject
("bring it back") — P3 reversibility. Reduced motion: springs become quick
fades, spins become stepped face changes, entry drop becomes a fade-in.

## Keyboard & DOM mirror
1/2/3 grab · arrows step faces · C face-off · L lock · X eject · U undo ·
Esc home. Face cards, tags, and the swap reasons are all real DOM anchored to
scene positions; a live region announces grabs, locks, ejects, swaps. The
boarding-pass tag column doubles as the tier-4 fallback (full scenario
walkable from tags alone).
